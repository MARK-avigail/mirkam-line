# בדיקת כשלים חמורים — 16 באוקטובר 2026

התרחישים להלן שוחזרו בהזרקת תקלות בסביבה מבודדת. אין ראיה שאירעו בשרת החי. שלושה כשלים מרכזיים נמצאו; רק הראשון הוכח כקריסת תהליך, ואין להציג את השניים האחרים כקריסות שרת.

## 1. משימת קול ברקע יכולה להפיל את תהליך Node
כאשר כתיבת תוצאת voice-job נכשלת, גם כתיבת מצב השגיאה עשויה להיכשל. Promise מנותק נשאר דחוי ללא טיפול. הבדיקה מפעילה Node נפרד עם unhandled-rejections=strict, מזינה callback חתום עם משלוח מדומה ומזריקה כשל בכתיבת תוצאת המשימה. לפני התיקון תהליך הילד יצא בקוד 1. אחרי התיקון הוא ממשיך עד כתיבת סמן הישרדות ויוצא בקוד 0.

תיקון: עדכון השיחה והמשימה בתוך transaction; טיפול אחרון שאינו כותב למסד נתונים ומדווח שדרושה התאוששות. אין חשיפה של נתוני לקוח בלוג הזה. תקלה מתמשכת במסד עדיין מחייבת טיפול/התאוששות; בלימת החריגה אינה תיקון דיסק מלא ואינה הבטחה שהשיחה המסוימת תושלם. סטטוס משלוח נשאר כפוף לרשומת message/delivery כדי למנוע ניסיון נוסף אחרי קבלה או מצב לא ודאי.

## 2. איפוס PIN חלקי יכול לפגוע בשחזור ובהרשאות
לפני התיקון ה-PIN הוחלף, ואז בוטלו tokens ונכתב audit כפעולות נפרדות. כשל במחיקת token משאיר PIN חדש שאינו מוחזר למנהלת בגלל השגיאה, ובמקביל התחברות ישנה עדיין תקפה. שוחזר כשל מחיקה לאחר כתיבת המשתמש, ונבדק חוסר השוויון מול הרשומה המקורית.

תיקון: שינוי PIN, ביטול sessions, ניקוי כשלי כניסה ו-audit בתוך transaction אחד. בכשל נשמר המצב הקודם; בהצלחה ה-PIN החדש תקף, הישן נדחה וכל tokens הישנים מבוטלים. אותו עיקרון יושם בחסימה/ביטול חסימה ונבדק כשל audit אחרי ביטול tokens.

## 3. רישום חלקי יוצר חשבון בלי למסור פרטי כניסה
יצירת user הצליחה לפני כשל audit, ולכן הבקשה נכשלה אף שהחשבון נשאר. ניסיון רישום מחדש נדחה ככפילות וה-PIN המקורי אינו ניתן לשחזור. אפשר היה לטפל בכך באיפוס ידני, אך זרימת הרישום שבורה. שוחזר עם audit שנכשל אחרי יצירת user.

תיקון: רישום ו-audit ב-transaction אחד; כשל אינו משאיר חשבון חלקי. אין שינוי בחשבונות קיימים או באלגוריתם יצירת הקודים.

## תיקון נוסף: כשל כתיבה למטמון
אחרי קבלת נכס תקין מהשרת, cache.put שנכשל (למשל מכסה מלאה) הפיל את כל מסלול ההצלחה וגרם לחזרה לקוד הישן. במצב ללא עותק שמור הוא עלול לגרום לתצוגת 503 אף שהרשת הצליחה. הבדיקה שיחזרה חזרה לקובץ ישן. כעת כשל השמירה המקומית אינו משליך את תשובת הרשת התקינה. אין בכך הבטחה לפתיחה ללא אינטרנט כאשר המטמון לא נשמר.
