# חיבור פקס יוצא — ניסיון InterFAX

קישור הרשמה: https://uplandsoftware.com/interfax/developer-registration/

אין צורך במכשיר פקס במשרד. חשבון הניסיון של הספק מוגבל ליעד ניסיון אחד; צריך יעד קבלה מאושר שאפשר לבדוק בו את המסמך. אין עדיין אימות מחיר לישראל או משלוח חי. אין לרכוש תוכנית על בסיס הנחת מחיר.

## מה נבנה
מתאם REST לפקס יוצא, PDF בעברית והנספחים הנתמכים, לאחר אישור החבילה והיעד במסלול הקיים. ההגדרה המקומית מגבילה שליחה למספר ניסיון אחד. לא נוסף פקס נכנס, ולא משלוח משולב email+fax. מסמכי הניסיון נשארים מסומנים לבדיקה.

קבלת אסמכתה מהספק אינה מסירה. בתיק המשתמש בניהול, בלשונית משלוחים, בעלת המערכת יכולה לבדוק את מצב הפקס. תשובת הספק מעדכנת לממתין, נמסר או נכשל. מסירה אינה אישור הגשה משפטית. אין סריקה אוטומטית ברקע.

המתאם אינו חוזר אוטומטית על POST. במצב לא ידוע יש לבדוק אצל הספק לפני שליחה נוספת; reference הוא מזהה התאמה ולא הבטחת מניעת כפילויות של הספק.

## הגדרה בשרת לאחר פתיחת חשבון
להזין פרטי API במפגש SSH פרטי בלבד, לא בצ׳אט או ב־GitHub. מתוך /opt/mirkam-line, לאחר משיכת הקוד:

```sh
python3 deploy/prepare-interfax.py
```

הסקריפט מבקש שם משתמש וסיסמה בהקלדה מוסתרת ומספר יעד בפורמט בינלאומי, שומר גיבוי פרטי ומעדכן רק את הגדרות הפקס ב־/opt/mirkam-private/runtime.env. הוא אינו שולח פקס ואינו מאמת חשבון. אין לשתף את קובץ הסביבה או הגיבוי.

לאחר ההגדרה נדרשת פריסה מלאה עם deploy/apply-voice-experience.sh, כדי שגם גשר הטלפוניה יתחבר מחדש לרשת היישום. אין עדות שהשלב בוצע כעת.

## בדיקת קבלה שעדיין נדרשת
מסמך ניסיון לא רגיש, אישור מפורש ליעד המאושר, משלוח אחד, בדיקת סטטוס ולבסוף בדיקת העמודים בצד המקבל. לבדוק עברית, מספר עמודים ונספחים. רק לאחר מכן לשקול הרחבת יעדים ושימוש תפעולי.

בדיקות מקומיות משתמשות בספק מדומה: אישור, הגבלת יעד, כתובת ספק, שגיאות, ללא משלוח חוזר, סטטוס, בידוד משתמשים וביטול הרשאות. הן אינן הוכחה למסירה חיה.

מקור API: https://rest.interfax.net/outbound/help
