# חסימת משתמש ומסירת קוד

בתיק המשתמש נוספו חסימה וביטול חסימה, עם אישור שמציג את שם המשתמש. הפעולה משתמשת במנגנון status הקיים: active=false, ביטול tokens ורישום audit. הרשומות אינן נמחקות. ביטול חסימה מחייב כניסה מחדש, ולא משחזר sessions קודמים. הקו משתמש ב-authenticate בכל צעד מאומת, ולכן token מבוטל נדחה בצעד הבא; אין הבטחה לביטול משלוח שכבר התחיל לפני החסימה.

קוד המשתמש ו-PIN הם שני מספרים בני שש ספרות הנוצרים ברישום. המערכת מציגה אותם לצוות למסירה פרטית למשתמש. אין כיום מסירה אוטומטית למתקשר או SMS. נוסף כפתור להצגה פרטית חוזרת של קוד המשתמש עם audit, ללא PIN או hash. ה-PIN נשמר כמגובב ואינו ניתן לשחזור; איפוס נותן PIN חדש. תצוגת פרטים מתנקה לאחר דקה או במעבר מסך. הרשאות owner/support לניהול משתמשים נשארות כפי שהוגדרו; billing ואורח אינם רשאים לראות את הקוד.

בדיקות: npm test — 1094 עברו, אפס כישלונות ואפס דילוגים. שש בדיקות חדשות: חסימה/ביטול ושמירת נתונים, ארבע בדיקות תפקידים להצגת קוד, וביטול חסימה בממשק והצגת קוד ללא PIN מומצא. UI נבדק באמצעות DOM מדומה; בדיקה חיה נדרשת לאחר התקנה.
