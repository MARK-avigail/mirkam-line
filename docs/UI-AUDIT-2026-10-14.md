# Functional review — 14 October 2026

## Confirmed and fixed in signed UI release 6

- Owner setup now renders its username/name fields in the initial setup section, without relying on a separate click to populate the distant admin panel. Results stay next to the form. Missing secret, invalid names and server errors produce visible feedback. The management key is cleared after successful creation.
- Navigation out of management to a member feature now hides management and brings the login form into view when needed.
- Administrative forms scroll into view; save operations report completion. Failures scroll the existing status into view rather than silently leaving it above the viewport.
- Empty users and office tickets now have explicit explanations.
- Application busy handling no longer indiscriminately enables the separate updater/connection buttons.
- Updater reports the current UI version after checking, so a generic “up to date” message is no longer the only evidence.

## Evidence and limits

223 local automated checks pass (96 core, 34 HTTP handler, 10 staff, 16 PWA, 31 native bridge, 23 updater, 13 UI execution checks). UI checks load the complete application script with a simulated DOM and mock HTTP responses. HTTP tests exercise the actual server handler and store separately. They are not Samsung touchscreen, Chromium rendering, or live provider tests. Chromium in this restricted execution environment failed to start because socket operations were denied.

The reported empty admin form could not be reproduced with the local script: its handler populated the expected fields. Release 6 removes that dynamic setup step; device verification is still required. Do not describe the exact original cause as established.

## Remaining release blockers / incomplete capabilities

- Codespaces remains a temporary backend, can stop, and has separate port access settings. Permanent hosting, persistent storage, HTTPS and backups remain necessary for production.
- First owner creation and MFA login must be verified on the user's actual server. Admin identity is separate from member code/PIN identity.
- Live AI credentials/credits and real provider response have not been verified in this review. Tests and UI error handling do not prove provider availability.
- Email requires SMTP configuration and a real delivery test; fax/payment are not connected. Telephony requires provider credentials and callback configuration.
- Cross-device access to server records exists; real-time synchronization, offline editing conflict handling and bidirectional remote control are not complete.
- Android document export/download and microphone operation require physical-device verification. A browser blob download does not establish native Android export support.
- Windows installer runtime is not exercised here. Prior desktop smoke results do not prove every user flow in this release.
- Private signing keys require durable secure backup. No private keys or account data are included in this document or repository changes.

Do not claim the entire system is ready or all bugs have been found. Continue with a first-owner end-to-end verification, then member chat/document flows against configured services.
