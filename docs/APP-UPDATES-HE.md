# עדכוני ממשק מתוך האפליקציה — 0.4.0

גרסה זו מוסיפה ל־Android ול־Windows הורדת שיפורי ממשק חתומים. בדיקה אוטומטית מתבצעת לאחר פתיחה; קיים גם כפתור בדיקה. ההורדה אינה סוגרת את המסך הפעיל. העדכון מופעל בהפעלה הבאה של התהליך, לאחר סגירה מלאה, ונשמר לשימוש ללא אינטרנט. אין צורך בשרת העסקי לצורך בדיקת העדכונים: המקור הקבוע הוא קבצים חתומים במאגר GitHub הציבורי.

מנגנון זה מחייב התקנת 0.4.0 תחילה. הוא אינו יכול להתווסף מרחוק ל־0.3.0/0.3.1. עדכוני Java, הרשאות, ספריות מקוריות וגשרים דורשים עדיין מתקין חדש. זו אינה הפצה דרך Google Play או Microsoft Store.

## אמון ושחזור

הקבצים מאומתים באמצעות RSA-SHA256 מול מפתח ציבורי שמוטמע בהתקנה. רק רשימת קובצי הממשק המדויקת מותרת; הגשר המקורי מועתק מההתקנה ואינו יורד מרחוק. מוגדרים גבולות גודל, פלטפורמה, גרסת תאימות ומספר גרסה עולה. חבילה לא חתומה, חלקית, ישנה או לא תואמת נדחית לפני שינוי הממשק. טעינה שלא הודיעה על סיום אתחול גורמת לחזרה לגרסה הקודמת בהפעלה הבאה. זו אינה הוכחה שאין באגים אחרי האתחול.

ETag מצמצם הורדות חוזרות. הגרסה הפעילה, הקודמת ועדכון ממתין נשמרים; גרסאות ישנות יותר מנוקות לאחר אתחול מוצלח. אסימוני חשבון ופרטים אישיים אינם נשלחים לשרת העדכונים. ב־Windows כתובת השרת נשמרת בנפרד מתיקיית גרסת הממשק.

## פרסום שיפור

לאחר שינוי הקוד והבדיקות:

```bash
node scripts/native/prepare.mjs
MIRKAM_UI_SIGNING_KEY_FILE=/secure/path/ui-update-private.pem node scripts/native/sign-update.mjs 3
```

המספר בדוגמה חייב להיות גדול מהגרסה האחרונה שפורסמה. מעלים את שני הקבצים `updates/android.json` ו־`updates/windows.json` ל־main. שינויים רק בתיקיית updates אינם מפעילים בניית APK או EXE. יש לבדוק חבילה לפני פרסום, ולתקן גרסה פגומה באמצעות מספר גבוה יותר.

המפתח הפרטי הראשוני נמצא בסביבת העבודה ב־`/workspace/.mirkam-release-secrets/ui-update-private.pem` בהרשאה 0600. הוא לא הועלה למאגר או לחבילת העדכון. יש לגבות אותו למקום מאובטח וקבוע לפני שהסביבה מוחלפת; אובדנו ידרוש התקנה עם מפתח ציבורי חדש. מפתח החתימה של APK נפרד: החל מ־0.4.0 הבנייה ב־GitHub מפיקה APK לא חתום, והחתימה מתבצעת מקומית באמצעות scripts/native/sign-android.sh ומפתח ההפצה ב־/workspace/.mirkam-release-secrets/android-release.p12. הסיסמה בקובץ פרטי סמוך. חומר זה לא מועלה ל־GitHub. מפתח הבדיקות הקודם לא נשמר ולכן ההתקנות הישנות דורשות החלפה חד־פעמית. יש לגבות את כל תיקיית המפתחות באופן פרטי ומתמשך לפני החלפת סביבת העבודה.

## בדיקות

בדיקות Node מכסות אימות חתימה, פלטפורמה, רשימת קבצים, גרסאות, הפעלה בפתיחה הבאה, שחזור ועדכון ללא רשת. הבנייה מפעילה בדיקת Windows נוספת שטוענת חבילת ממשק חתומה בתוך התוכנה. הצלחה במכשיר Samsung עדיין מחייבת בדיקה לאחר התקנה.
